# Генерация Lottie-анимаций из медиаторов

Памятка для сессий Claude Code: как собрать новую анимацию из шести PNG-заготовок в этой папке.

## Промпт-шаблон

> Прочитай `assets/animations/PROMPT.md` и сделай по нему новую Lottie-анимацию.
>
> **Название:** `<kebab-case-имя>`
> **Идея:** `<описание движения в 1–3 предложениях>`
> **Длительность:** `<N>` секунд, бесшовная петля
> **Порядок медиаторов:** `<файлы через запятую, либо «на твой вкус»>`
> **Где показать:** `<экран или «нигде, просто собери файл»>`
>
> Собери `.lottie`, прогони валидацию из памятки и покажи, что проверил.

Всё, что ниже — справочник, который отвечает на вопросы «как именно».

## Заготовки

Шесть PNG в этой папке, все **80×86**, RGBA с прозрачностью, одна и та же форма медиатора в разных цветах:

`black.png`, `fire.png`, `red_dark.png`, `red_light.png`, `yellow_down.png`, `yellow_top.png`

**Острый (тонкий) конец медиатора смотрит вверх**, то есть в сторону `−Y`. Это отправная точка для всех расчётов поворота.

## Конвейер

1. Написать `assets/animations/<name>.json` — обычный Bodymovin v5 JSON.
2. `npm run build:lottie` — упакует **все** `.json` из этой папки в одноимённые `.lottie`, вшив PNG в base64.
3. Показать в приложении:
   ```tsx
   <LottieAnimation source={require("@/assets/animations/<name>.lottie")} size={220} />
   ```

Нативная пересборка клиента нужна **только один раз** — `lottie-react-native` уже установлен. Новый ассет подхватывается перезагрузкой бандла (`r` в Metro).

## Как писать JSON

Руками не пишите — 6 слоёв с кейфреймами набираются с ошибками. Напишите одноразовый Node-скрипт в scratchpad-папке сессии, который считает геометрию и печатает JSON. Итерации («поменяй порядок», «убери пульсацию») тогда стоят одну правку в скрипте вместо ручного редактирования 13 КБ.

### Композиция

```json
{ "v": "5.9.0", "fr": 60, "ip": 0, "op": 360, "w": 512, "h": 512,
  "nm": "<name>", "ddd": 0, "assets": [...], "layers": [...], "markers": [] }
```

`op` = длительность в кадрах (60 fps, то есть 6 с = 360).

### Ассеты

```json
{ "id": "image_0", "w": 80, "h": 86, "u": "", "p": "black.png", "e": 0 }
```

`u: ""` и имя файла в `p` — обязательно: `scripts/build-lottie.mjs` по этим полям находит PNG и подменяет их на base64. Один ассет можно переиспользовать в любом числе слоёв, в `.lottie` он попадёт один раз.

### Слой-медиатор

```json
{
  "ddd": 0,
  "ind": 2,
  "ty": 2,
  "nm": "outer-0",
  "refId": "image_0",
  "parent": 1,
  "sr": 1,
  "ao": 0,
  "ip": 0,
  "op": 360,
  "st": 0,
  "bm": 0,
  "ks": {
    "o": { "a": 0, "k": 100 },
    "r": { "a": 0, "k": 90 },
    "p": { "a": 0, "k": [150, 0, 0] },
    "a": { "a": 0, "k": [40, 43, 0] },
    "s": { "a": 0, "k": [105, 105, 100] }
  }
}
```

`a` — точка привязки, всегда `[40, 43, 0]` (центр картинки 80×86). `ind` уникален, `parent` ссылается на чужой `ind`.

### Орбита через null-слой

Не анимируйте позицию по окружности кейфреймами. Заведите null-слой (`ty: 3`) в центре, крутите его, а медиаторы прицепите к нему с **фиксированными** позициями:

```json
{
  "ddd": 0,
  "ind": 1,
  "ty": 3,
  "nm": "outer-ring",
  "sr": 1,
  "ao": 0,
  "sw": 100,
  "sh": 100,
  "sc": "#000000",
  "ip": 0,
  "op": 360,
  "st": 0,
  "bm": 0,
  "ks": {
    "o": { "a": 0, "k": 0 },
    "r": {
      "a": 1,
      "k": [
        { "i": { "x": [1], "y": [1] }, "o": { "x": [0], "y": [0] }, "t": 0, "s": [0] },
        { "t": 360, "s": [360] }
      ]
    },
    "p": { "a": 0, "k": [256, 256, 0] },
    "a": { "a": 0, "k": [0, 0, 0] },
    "s": { "a": 0, "k": [100, 100, 100] }
  }
}
```

Позиция ребёнка отсчитывается от центра родителя, так что `i`-й медиатор на кольце радиуса `R`:

```
angle_i = -90 + i * (360 / count)        // -90 = верх, дальше по часовой
p       = [R * cos(angle_i), R * sin(angle_i), 0]
r       = angle_i + 90                   // остриём наружу
r       = angle_i - 90                   // остриём в центр
```

Отрицательное значение в `r` у null-слоя (`-360`) крутит кольцо против часовой.

### Кейфреймы

Анимированное свойство: `{ "a": 1, "k": [<кейфреймы>] }`, статичное: `{ "a": 0, "k": <значение> }`.

- У последнего кейфрейма только `t` и `s` — без `i`/`o`.
- `t` строго возрастает, первый `t` = 0, последний `t` = `op`.
- Линейно: `"o": {"x":[0],"y":[0]}, "i": {"x":[1],"y":[1]}`
- Плавно (easeInOut): `"o": {"x":[0.6],"y":[0]}, "i": {"x":[0.4],"y":[1]}`

`o` — исходящая касательная текущего кейфрейма, `i` — входящая следующего; вместе это контрольные точки кубической кривой.

### Бесшовная петля

Главное требование — иначе на стыке будет рывок:

- значение каждого анимированного свойства на кадре `0` и на кадре `op` **совпадает**;
- исключение — поворот: `0 → 360` (или `0 → -360`) выглядит непрерывно;

### Границы холста

```
R + hypot(80, 86) / 2 * scale / 100 ≤ 256
```

Половина диагонали ≈ 58.7 px при 100%. Для `R = 150` и `scale = 105` получается ≈ 211 — влезает.

## Валидация перед сдачей

Визуально проверить нечем, поэтому прогоняйте JSON скриптом. Что имеет смысл проверять:

- каждый `refId` есть в `assets`, каждый `parent` есть среди `ind`;
- `t` возрастает, диапазон ровно `0..op`;
- стык петли: `k[0].s` равно `k.at(-1).s` для всего, кроме поворота;
- ориентация: `r` равен `angle ± 90` от фактического направления на `p`;
- вписанность в холст по формуле выше.
